# 周三展示底稿（口语版）

> 目标：不用背稿，记住每段的“一句话”，其余现场看着图讲。
> 顺序：CART → K-Means → 二分 K-Means → 改进 → DBSCAN → 层次聚类 → 对比收尾。

## 开场（20 秒）

“我这次做了两个小项目：一个是分类的 CART 决策树，一个是聚类的 K-Means 系列。共同点是算法全部手写，只用 NumPy，没有调 sklearn 的模型；前端负责把每一步录下来回放，所以能看到算法‘怎么想’的。”

如果老师问数据集：分类用 sklearn 的 Iris；聚类用 UCI Seeds 和 Wine，另外自己造了双月数据做对比。

## 1. CART（约 90 秒）

**一句话（背这个）**

> 每个节点把每个特征排个序，扫一遍所有相邻不同值的中点，算左右两边的加权 Gini，挑不纯度最低的切一刀；两边递归，直到纯了或者碰到限制。

**展开讲**

1. 连续特征不能穷举，只试“能改变分组”的位置：排序后相邻两个不同取值的中点。比如 1.9 和 3.0 中间没有样本，切 2.45 就行。
2. 每个候选算：

   Gini = 1 − Σ pₖ²，加权 Gini = (n左/n)·Gini左 + (n右/n)·Gini右。

3. 选加权 Gini 最小的；平局按（Gini，特征下标，阈值）定，保证可复现。
4. 递归下去，停止条件：节点纯、到最大深度、叶样本太少、没有合法切点、增益不够。

**数字（记两三个就够）**

- 根节点 90 个训练样本，4 个特征，一共只有 104 个候选切点（不是 90×4）。
- 选中的是花瓣长度 2.45，加权 Gini 0.333，增益 0.333。
- 整棵树评估 301 个候选。
- 后剪枝：7 个叶 → 4 个叶，测试准确率 0.933 → 0.967。

**剪枝一句话**

> 先把树长完整，再给每个内部节点算“合并它平均每个叶子要多付多少不纯度”，每次合并最便宜的那棵，最后拿验证集挑一个 α。

**可能被问**

- 为什么不用信息增益？Gini 不用算 log，多分类直接算，CART 本来就用 Gini。
- 为什么剪枝不用测试集？测试集只在最后看一次，选 α 用验证集。
- 剪枝一定更好吗？不一定，它主要换更小的树和更稳的结果；20 组划分上测试准确率是持平略升。

## 2. K-Means（约 40 秒）

**一句话**

> 先随便撒 K 个中心，每个点找最近的中心分堆，再拿每堆的平均值当新中心，反复直到中心不动。

**展开讲**

- 目标：SSE = Σ 每个点到它中心距离的平方。
- 两步循环：分配（找最近中心）→ 更新（算均值）。
- 收敛：中心位移小于 tol，或者分配不再变化。
- 空簇处理：找离自己中心最远的点补过去。
- 复杂度大约 O(n·K·d·迭代数)。

**数字**

- Seeds，K=3，20 个种子：平均 SSE 430.81，ARI 0.780，轮廓系数 0.402，平均 8 次迭代。
- Wine：平均 SSE 1310.45，但标准差 92.85，说明初始化影响很大。

**坑**

- 对初始化敏感；K 要自己定；假设簇是“球形、差不多大”。

---

## 3. 二分 K-Means（约 40 秒）

**一句话**

> 先所有点当一个簇，每轮挑一个簇，用 K=2 的 K-Means 劈成两半，劈到 K 个簇为止。

**展开讲**

- 外层：选哪个簇劈；基线是挑 SSE 最大的。
- 内层：对选中的簇跑普通 K-Means（K=2）。
- 每次内部迭代都录一帧，所以时间轴能一帧一帧看：选中簇 → 两个新中心 → 点换颜色 → 分裂完成。

**数字**

- Seeds 演示：最终 SSE 460.62，ARI 0.7545，轮廓 0.3815。
- 它 SSE 比标准 K-Means 高，因为叶簇分完就不再重分配；它的价值是过程清楚、能画树。

---

## 4. 改进（约 40 秒）

三个改动，逐个说：

1. **K-Means++ 初始化**：第一个中心随便选，后面的按“离已有中心越远越容易被选”的概率挑。
2. **多次重启择优**：每次二分内部跑 5 次，取 SSE 最低的那组。
3. **按全局 SSE 降幅选簇**：不是只看哪个簇最大，而是每个候选都试着劈一次，选让整体 SSE 掉得最多的。

**数字**

- Seeds：B0（随机 + 最大簇）454.43 → B1（++ 和重启）448.93，SSE 降 5.50。
- Wine：B0 1342.80 → B1 1329.28，降 13.20；耗时约 3 倍。
- K=8 时 B2 比 B1 再低一点：Seeds 262.46 → 260.37。

**一定要说的一句实话**

> 改进不是所有时候都更好。SSE 降了，但 Seeds 的 ARI 从 0.748 掉到 0.742，所以我在报告里是分开看 SSE、ARI 和耗时的。

## 5. DBSCAN（约 50 秒）

**一句话**

> 够密的地方算核心点，从核心点把 eps 范围内的邻居拉进同一簇，邻居也是核心就继续扩散；拉不到任何簇的点是噪声。

**三个概念**

- 核心点：eps 半径内（含自己）至少 min_samples 个点。
- 边界点：自己不核心，但落在某个核心点的圈里。
- 噪声：两个都不是，标签 −1。

**演示图（重点）**

- 双月数据：K-Means 只能横着切，ARI 0.23；DBSCAN 沿着两条弯月走，ARI 1.00。
- 这张图最直观：K-Means 假设“圆球”，DBSCAN 只看“密度连不连”。

**Seeds 上的坑**

- eps=0.8：3 个簇，但 59 个点被判噪声，ARI 0.273。
- eps 再大就并成一个大簇；说明 DBSCAN 对 eps 很敏感，高维空间里距离都差不多，更难选。
- 所以它强在形状任意、能识别噪声，弱在密度不均匀和高维。

---

## 6. 层次聚类（约 40 秒）

**一句话**

> 每个点先自成一簇，每次合并最近的两个簇，一直合并到一个簇；把合并过程画成树，想要几类就在对应高度切一刀。

**展开讲**

- 我用 average linkage：两簇的距离 = 所有点对距离的平均。
- 合并后更新距离：

  d(A∪B, C) = (|A|·d(A,C) + |B|·d(B,C)) / (|A|+|B|)。

- 树状图的高度就是合并时的距离；在高度 2 左右切，得到 3 个簇。
- 优点：不用先定 K，能看到层次；缺点：朴素实现 O(n³)，合并了就不能反悔。

**数字**

- Seeds 每类取 30 个（共 90），average linkage 切 3 簇：ARI 0.8115，轮廓 0.4367。

## 7. 收尾对比（20 秒）

| | K-Means | DBSCAN | 层次 |
| --- | --- | --- | --- |
| 要不要 K | 要 | 不要 | 不强制，切树即可 |
| 形状 | 球形 | 任意 | 看链接方式 |
| 噪声 | 全部分配 | 能标噪声 | 全部分配 |
| 复杂度 | 低 | O(n²) | 朴素 O(n³) |
| 可解释 | 中心 | 密度 | 树状图 |

一句话收尾：

> 没有哪个算法全面更好。数据是球形就用 K-Means；形状怪、有噪声就试 DBSCAN；想看层次关系就用树。

## 老师可能追问（短答）

1. **Gini 为什么比熵快？** 不用 log，只有乘加。
2. **候选切点为什么取中点？** 同一空隙里任何值分组都一样，中点只是代表。
3. **K-Means 一定收敛吗？** 会，SSE 每步不增，且状态有限。
4. **K-Means++ 为什么有用？** 让初始中心尽量分开，减少落入局部最优。
5. **二分 K-Means 为什么 SSE 更高？** 叶簇不再参与全局重分配。
6. **DBSCAN 参数怎么选？** 看 k-距离曲线拐点；或者像我们这样扫描 eps 看簇数和噪声比例。
7. **层次聚类怎么定 K？** 看树状图高度差，或者结合轮廓系数。
8. **ARI 和 SSE 为什么可能打架？** SSE 只看紧凑，ARI 看和真实类别是否一致。
9. **代码在哪？** `algorithms/` 下：`cart.py`、`kmeans.py`、`bisecting.py`、`improved.py`、`dbscan.py`、`hierarchical.py`。
10. **哪里用了库？** 只有 NumPy 和矩阵运算；ECharts 只负责画图。
