## 1. 标准 K-Means（完整讲，约 100 秒）

**代码位置**（`KMeansLab/`）

- 主循环：`algorithms/kmeans.py` → `_fit`（初始化 → 分配 → 更新 → 收敛判断）
- 分配 / 空簇修复：同文件 `_nearest`、`assign_clusters`、`_nonempty_labels`
- 更新中心：同文件 `update_centers`
- 随机选点：`algorithms/initialization.py` → `initialize_centers`（`method="random"`）
- SSE：`core/metrics.py` → `calculate_sse`

### 一句话

> 随机撒 K 个中心 → 每个点归最近中心 → 中心挪到簇均值 → 重复到中心不动。

### 要提到的点

- 目标函数 SSE：簇内平方误差和，越小越紧凑。
- 两步循环：**分配**（最近中心）、**更新**（簇均值）。
- 终止条件有三种（见下面「终止条件」）：位移够小、分配不变、达到最大迭代。
- 空簇处理：找离中心最远的点补进去。老师说的「**空类错**」是另一种情况：初始中心恰好选到很偏的点，会形成只有一两个点的小簇，怎么迭代都拉不回来——对策是 K-Means++ 初始化和多种子重复（二分那边是多次重启）。
- 初始化：随机选 K 个样本（老师课上的默认做法）；种子不同结果不同，所以要多种子比较。
- K 的选择：老师课上的**手肘法**——扫不同 K、看 SSE 下降的拐点；我们的对比实验就是 K=1–8。
- 局限（老师课上的三类数据）：大小/密度不均匀（异构簇）、非球状（条带）、有离群点，效果都会变差。

### 操作 + 时间轴（实际 7 帧）

| 帧 | 事件 | SSE | 台词 |
| ---: | --- | ---: | --- |
| 0 | 初始 | 953.65 | “随机挑了 3 个点当中心，每个点按最近中心先归了堆。中心还是随机点，所以 SSE 953，起点很差。” |
| 1 | 迭代 1 | 561.44 | “这一帧是**挪中心**：中心挪到各自那一堆的均值上。堆没变，SSE 直接从 953 掉到 561。” |
| 2 | 迭代 2 | 435.87 | “按新中心**重新分堆**，再挪一次中心，436。前期猛降。” |
| 3–5 | 迭代 3–5 | 433.36 → 431.20 → 430.82 | “后面每轮只微调，中心基本不动。” |
| 6 | 收敛 | 430.82 | “这一轮按新中心重新分堆，结果和上一轮完全一样，判定收敛、停止。总共 5 次迭代，停止原因是 stable_assignment（分配不再变化）。” |

### 终止条件（三种，按代码里的判断顺序）

每一轮「挪完中心」之后依次检查，命中任意一个就停：

| 顺序 | 条件 | 代码（`_fit`） | 停止原因 |
| ---: | --- | --- | --- |
| 1 | 中心的最大位移 ≤ `tol`（默认 1e-6） | `if shift <= tol:` | `tolerance` |
| 2 | 按新中心重新分堆，结果和上一轮一样 | `if np.array_equal(next_labels, labels):` | `stable_assignment` |
| 3 | 前两个都没触发，循环跑满 `max_iter`（默认 100） | `for ... else:` | `max_iter` |

- 这次演示命中的是**第 2 种**：第 5 轮中心位移 0.021，还没小于 tol，但分配已经不变，所以停。
- 最后一帧的「附加信息」里能看到停止原因。
- 为什么可以停：分配不变 → 下一轮中心也不变 → 再跑结果完全一样。
- 二分 K-Means 内部那一层（K=2）用的也是这三个条件。

### 读数

- 三个簇 **69 / 70 / 71** 个点，很均衡。
- ARI **0.8112**，轮廓系数 **0.4029**。
- 20 个种子平均 SSE **430.81 ± 0.19**、平均 **8.05** 次迭代，说明在这份数据上很稳。

### 别说错

> 顺序就是“随机选点 → 分堆 → 挪中心 → 重复”，也就是程序录帧的顺序。
> 但**不是“算周围点的 SSE，符合要求才画出簇”**：分堆只看最近中心，SSE 是每轮结束后的分数，用来观察下降和判断收敛，不是画簇的条件。

### 可能被问

- 为什么一定收敛？每轮 SSE 不增，分配状态有限。
- 为什么只迭代 5 次就停？命中了第 2 种终止条件（分配不再变化），再跑结果也一样。
- K 怎么定？看业务，或扫 K 看 SSE 拐点。
- 空类错和空簇是一回事吗？不完全是：空簇是 0 个点（代码里补点修复）；空类错是初始中心选偏、形成一两个点的小簇，靠 K-Means++ / 多次重启避免，必要时把离群点当噪声删掉。
- 老师说的后处理怎么做？很小很小的簇（一两个点）当离群点删掉；特别大的簇（占八九成）再分一次。我们的界面没自动做，但聚类统计里能直接看到这两种情况。
- 复杂度？O(n·K·d·迭代)，就是老师课上的 n×k×i×d。

## 2. 二分 K-Means · B0（只讲新增，约 70 秒）

**代码位置**（`KMeansLab/`）

- 主循环：`algorithms/bisecting.py` → `_fit`
- 选簇（SSE 最大）：`_fit` 里 `strategy == "max_sse"` 那两行
- 内部 K=2 与重启：同文件 `_candidate`（调用 `kmeans._fit(..., 2, ...)`）
- 增益：`_candidate` 返回的 `gain = parent.sse - winner.sse`
- 帧事件：`split_selected / split_initial / iteration / split_complete`
- 界面：`frontend/js/charts.js` → `renderTree`（分裂树）、`frontend/js/timeline.js`（时间轴）

### 一句话

> 全部点先当一个簇，每轮挑一个簇用 K=2 再劈一次，劈到 K 个为止。

### 只讲新增的点

- **外层**：选哪个簇劈。老师课上的基线是劈**样本数最多**的簇；我实现的是劈 **SSE 最大** 的簇——两者都是启发式，SSE 直接对应目标函数，样本多但很紧的簇未必值得劈。
- **定位**：老师课上把二分 K-Means 归为**由总到分的分裂式层次聚类**；标准 K-Means 是**基于划分的聚类**。
- **内层**：对选中的簇跑一次普通的 K=2 K-Means。
- **叶簇固定**：劈完就不再参与全局重分配，所以最终 SSE 通常比标准 K-Means 高。
- **多了一棵分裂树**：每次分裂长出两个子节点，能看出层次。
- **帧更多**：选中分裂 → 初始化子簇 → 内部迭代 → 分裂完成，每一帧都能回放。

### 老师课上的两个说法

- “K-Means 是全局最优，二分是局部最优”：因为 K-Means 每轮所有点都能重新分配，二分一旦劈开就回不去。严格讲 K-Means 收敛到的是 SSE 的**局部最优**（受初始化影响），区别在于它始终可以全局重分配。
- “K=10 要劈 9 次”：和我们的 K−1 轮一致；每次劈完叶簇数 +1。

### 操作 + 时间轴（实际 19 帧）

- 初始：整簇，SSE **1470.00**。
- **帧 10**：第一次分裂完成，根簇分成两个。
- **帧 17**：第二次分裂完成，得到 3 个簇。
- 最终 SSE **460.62**，ARI **0.7545**，轮廓 **0.3815**，簇大小 **80 / 63 / 67**。

台词：

> “跟标准 K-Means 比，它不是一次分 K 个，而是从 1 个簇开始一层层劈。每次劈的是当前 SSE 最大的那个簇，内部还是 K=2 的 K-Means。劈完的簇就固定了，所以 SSE 460 比标准 K-Means 的 430 高；换来的是这棵分裂树，能看出它是怎么一步步分出来的。”

### 数字对比（20 个种子，K=3）

| 算法 | 平均 SSE | ARI | 轮廓 |
| --- | ---: | ---: | ---: |
| 标准 K-Means | 430.81 | .7800 | .4019 |
| B0 | 454.43 | .7479 | .3865 |

### 可能被问

- 为什么 SSE 更高？叶簇不再全局重分配。
- 为什么还要用它？过程可解释、能画树，这是展示的重点。

## 3. 改进二分 · B2（只讲改进点，约 70 秒）

**代码位置**（`KMeansLab/`）

- 入口（一组默认参数）：`algorithms/improved.py`（`init_method="kmeans++"`、`restarts=5`、`strategy="max_gain"`）
- 实际逻辑：`algorithms/bisecting.py` → `_fit`
  - A · K-Means++：`algorithms/initialization.py` → `initialize_centers`（`method="kmeans++"`）
  - B · 多次重启：`algorithms/bisecting.py` → `_candidate`（`for index, seed in enumerate(seeds)`）
  - C · 降幅选簇：`_fit` 里只有 `strategy == "max_sse"` 才筛候选；`max_gain` 时所有叶簇都试劈，再按 `gain` 选最大的
- 对比实验数据：`app/services.py` → `VARIANTS`、`compare_algorithms`

### 一句话

> 在二分 K-Means 上加三件事：K-Means++ 初始化、多次重启择优、按全局 SSE 降幅选簇。

### 三个改进（只讲这些）

1. **A · K-Means++ 初始化**：第一个中心随机，后面的按距离平方加权选，尽量分开。
   $$P(x) = D(x)^2 / \sum D(x)^2$$
2. **B · 多次重启择优**：每个候选簇内部跑 5 次 K=2，取 SSE 最低的那组。
3. **C · 全局 SSE 降幅选簇**：不是只劈最大的簇，而是每个候选都试劈一次，选让整体 SSE 掉得最多的：
   $$\Delta J = J(C) - [J(C_1) + J(C_2)]$$

### 为什么这么改（一句话记）

- **A**：把起点选好，让初始中心彼此分散。
- **B · 多次重启**：**减少随机初始化对结果的负面影响**。老师课上提到“随机选点可能要做好多次才能出好结果”——B 就是把这件事自动化：同一刀多试 5 次、只留 SSE 最低的那次。
- **C · 降幅选簇**：让每一轮的贪心选择更准。原来“劈 SSE 最大的簇”只是一个代理指标，最大的簇不一定最好劈；改成直接比“劈完整体 SSE 掉多少”，降低因为选错簇而落进较差局部最优的风险。

### 数字

- Seeds：B0 **454.43** → B1 **448.93**（−5.50）。
- Wine：B0 **1342.80** → B1 **1329.28**（−13.20），耗时约 3 倍。
- K=3 时 B1 和 B2 结果一样（都是 448.93）；K=8 时 B2 才比 B1 低：Seeds **262.46 → 260.37**。
- B2 在 K=8 时评估 28 个候选，B1 只评估 7 个。

### 这次演示（seed 42）

- 14 帧，SSE **446.87**，ARI **0.7397**，轮廓 **0.3927**，簇大小 77 / 70 / 63。

### 一定要说的实话

> “改进不是所有时候都更好。SSE 降了，但 Seeds 的 ARI 从 .7479 掉到 .7419，耗时也多了约 3 倍。所以我在报告里是 SSE、ARI、耗时分开看的。”

### 别说错

> 老师课上也说二分是局部最优；C 不是“让算法跳出局部最优”。二分 K-Means 仍然是贪心的，劈完的叶簇也不会再重分配；C 只是把“选哪个簇”的依据从代理指标换成了真实增益。所以 K=3 时 B1 和 B2 完全一样，K=8 才差 2 左右。

### 可能被问

- K-Means++ 有什么用？让初始中心彼此分散，降低一开始就落进差的局部最优的概率。
- B2 为什么 K 小的时候没用？候选少，试算多花时间但选不出差别。

## 5. DBSCAN（完整讲，约 75 秒）

**代码位置**（`KMeansLab/`）

- 算法：`algorithms/dbscan.py` → `fit`
  - 核心点：`neighbour_counts = neighbours.sum(axis=1)`、`core_mask = neighbour_counts >= min_samples`
  - 连通扩张：`for seed in range(n)` 里的 `queue`
- 接入界面：`app/services.py` → `_run_dbscan`
- 散点噪声标记：`frontend/js/charts.js` → `renderScatter`

### 一句话

> 够密的地方是核心点，从核心点把 eps 范围内的邻居拉进同一簇，邻居也是核心就继续扩散；拉不到的是噪声。

### 要提到的点

- **核心点**：eps 邻域内（含自己）至少 `min_samples` 个点；邻居与它是**密度直达**。
- **边界点**：自己不核心，但落在某个核心点的邻域里。
- **密度可达 / 密度相连**：通过一串核心点传过去是密度可达；同属一个核心点邻域的两个边界点是密度相连。
- **簇的定义**（老师课上的原话）：由密度可达关系导出的**最大密度相连集合**；到不了任何这种集合的点就是**噪声**（标签 −1）。
- 所以 DBSCAN 是**部分聚类**：允许有些点不归簇；不需要 K，也没有迭代、质心和 SSE。

### 操作 + 页面

选 **DBSCAN**，`eps=0.8`、`min_samples=5`，运行。

- 散点里红色 × 是噪声；虚线是簇的凸包。
- 右侧：**3 簇 / 59 噪声**，核心点 113，边界点 38。
- 簇大小 **107 / 15 / 29**。
- ARI **0.273**，轮廓 **0.3755**（只在非噪声点上算）。
- 时间轴、分裂树、SSE 自动换成“不适用”，因为算法没有这些中间状态。

### 参数敏感（一定要说）

| eps | 簇数 | 噪声 |
| ---: | ---: | ---: |
| 0.8 | 3 | 59 |
| 1.0 | 1 | 13 |
| 1.2 | 1 | 6 |

> “eps 调到 1.0，三个簇就被连成一个了。所以 DBSCAN 强在形状任意、能识别噪声，弱在参数敏感、高维不好选 eps。”

注意：eps 是**标准化后**的邻域半径（老师说的邻域半径），不是原始单位。

### 可能被问

- 核心点怎么来的？逐个数邻居，≥ min_samples 就是。
- ARI 为什么低？28% 是噪声，而且密度簇不等于品种。
- PCA 影响结果吗？不影响，聚类在 7 维标准化特征上算，PCA 只负责显示。
- ARI 和轮廓系数是什么指标？ARI 是外部指标（老师课上的 RI / JC / F1 同类，ARI 扣掉了随机一致的部分）；轮廓系数是内部指标。

## 6. 层次聚类（完整讲，约 75 秒）

**代码位置**（`KMeansLab/`）

- 算法：`algorithms/hierarchical.py` → `fit`（找最近两簇 `np.argmin(masked)`；按 `linkage` 更新距离）
- 切树：同文件 `Hierarchy.cut`
- 接入界面：`app/services.py` → `_run_hierarchical`
- 树状图：`frontend/js/charts.js` → `renderDendrogram`；合并距离曲线 → `renderMergeCurve`

### 一句话

> 每个点先自成一簇，每次合并最近的两簇，直到只剩一个；把合并过程画成树，想要几类就在对应高度切一刀。

### 要提到的点

- 三种链接：**单链**（single / min）、**全链**（complete / max）、**平均链**（average）。老师课上的结论：单链对噪声/异常点非常敏感（一个最近点就能把簇拉过去），全链更稳但容易把大类劈开、偏好球状簇，平均链介于两者之间、表现更像全链。
- average 的更新公式：
  $$d(A\cup B,C)=\frac{|A|d(A,C)+|B|d(B,C)}{|A|+|B|}$$
- 树状图：纵轴是合并距离，越高越晚合并；黄色虚线是切 `K=3`。
- 没有噪声、没有质心、没有随机性；离群点表现为最后合并的高分支。
- **两个方向**（老师课上的分类）：由总到分的**分裂式**（二分 K-Means 就是例子）和由分到总的**凝聚式**（我们这里做的）。
- 每合并一次，都要更新一次**临近度矩阵**（proximity matrix）；我们代码里就是那张 n×n 的距离矩阵。

### 操作 + 页面

选 **层次聚类**，`average linkage`，`K=3`，运行。

- 中间是树状图；右边“合并距离”曲线的黄色虚线就是切 K 的位置。
- 合并次数 **209**（210 − 1），耗时约 25 ms。
- 全量 Seeds：ARI **0.686**，轮廓 **0.376**。
- 每类取 30 个（共 90）画树更清楚：ARI **0.8115**，轮廓 **0.4367**。
- 停止条件：达到预设簇数就切；不切就得到整棵树，用来看层次结构（老师说的探索性用法）。

### 局限（主动说）

- 朴素实现 O(n³)，210 个点没问题，上万点要换算法；要维护 n×n 的临近度矩阵，内存 O(n²)。
- 老师课上把层次聚类也归为**局部最优**：合并不可撤销。
- 结果依赖 linkage 和距离度量，所以一定要标准化。
- 老师课上还提到：不确定用哪种链接时，可以把几种都跑一遍、用评价指标挑最好的——我们的界面能手动切 linkage 对比，但没有自动选优。

### 可能被问

- K 怎么选？看树高的跳变，或结合轮廓系数。
- 和 K-Means 差在哪？层次给的是不同粒度的结构，K-Means 优化的是 SSE。
- 有噪声吗？没有；离群点最后才合并，在树上是一根高竖线。

## 8. CART（分类，最后讲，约 2 分钟）

**代码位置**（`CARTLab/`，另一个仓库）

- 建树：`algorithms/cart.py` → `gini`、`candidate_splits`（候选切点搜索）、`fit` 里的 `grow`（递归建树）
- 剪枝：`algorithms/pruning.py` → `prune_sequence`（弱链接系数）、`best_step`（验证集选 α）
- 指标：`core/metrics.py` → `confusion_matrix`、`classification_report`
- 界面：`frontend/js/charts.js` → `renderTree`、`renderCandidates`、`renderConfusion`、`renderPruneCurve`

### 一句话

> 遍历所有特征，按每个特征把节点里的样本排序，对每个切点算 Gini，选不纯度最低的那一刀把节点分开，左右两边递归。

### 操作

打开 CARTLab：数据集 Iris，`seed=42`，`max_depth=4`，勾选「代价复杂度后剪枝」，点「运行训练」。

### （1）建树 —— 拖建树时间轴

- 根节点：90 个训练样本，类别 [30 / 30 / 30]，Gini **0.667**。
- 候选表第一行：**花瓣长度 ≤ 2.45**，加权 Gini **0.333**，增益 **0.333**。
  - 2.45 是 1.9 和 3.0 的中点：setosa 花瓣最长 1.9，其余最短 3.0，中间没有样本。
- 第二行：花瓣宽度 ≤ 0.75，**同分**（同样是 30 / 60 的分组）→ 平局取特征下标小的，所以选花瓣长度。
- 左边 30 个全是 setosa → 纯节点，直接成叶。
- 右边 60 个 [0 / 30 / 30] → 继续用 **花瓣长度 ≤ 5.05** 分，再往下用 **花瓣宽度 ≤ 1.65**。
- 节点上的“构建中”：深度优先递归，这棵子树还没建完，不是报错。
- 根节点只评估了 **104** 个候选切点，整棵树 **301** 个。

### （2）读最终的树（剪枝后 4 个叶）

| 位置 | 条件 | 去向 |
| --- | --- | --- |
| 根 | 花瓣长度 ≤ 2.45 | 左：setosa（30 个，全对） |
| 右子树 | 花瓣长度 ≤ 5.05 | 右：virginica（28 个，27 个是） |
| 其左子树 | 花瓣宽度 ≤ 1.65 | 左：versicolor（27 个，纯）；右：virginica（5 个，3 个是） |

### （3）剪枝 —— 切到「剪枝」轨道

对每个内部节点算弱链接系数：

$$\alpha_{eff}(t)=\frac{R(t)-R(T_t)}{|T_t|-1}$$

每轮剪掉 α_eff 最小的子树，α 由**验证集**选：

| α | 叶数 | 训练 | 验证 | 测试 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 7 | .989 | .933 | .933 |
| .0107（剪 #6） | 5 | .978 | .933 | .933 |
| **.0119（剪 #12）** | **4** | .967 | **1.000** | **.967** |
| .0338（剪 #5） | 3 | .956 | .933 | .867 |
| .2515 | 2 | .667 | .667 | .667 |
| .3333 | 1 | .333 | .333 | .333 |

- 验证集在 α = 0.0119 时最高，选 **4 个叶**；测试集只在最后看一次：**0.967**。
- 20 组划分：叶节点 **6.4 → 3.45**，验证 **.938 → .950**，测试 **.947 ± .036 → .940 ± .029**（持平，波动更小）。

### （4）指标（测试集 30 个）

- 混淆矩阵 `[[10, 0, 0], [0, 10, 0], [0, 1, 9]]`，准确率 **29 / 30 = 0.967**。
- 精确率 / 召回率：
  - setosa：1.000 / 1.000
  - versicolor：10/11 = **0.909** / 10/10 = **1.000**
  - virginica：9/9 = **1.000** / 9/10 = **0.900**
- 唯一错的一个：一个 virginica 被判成 versicolor。
- 宏平均：精确率 .970、召回率 .967、F1 .967。
- 推理路径：选一个测试样本，每层显示比较条件、Gini、类别计数，直到叶节点给出预测。

### 别说错

- CART 是**分类**（有标签），前面几个都是**聚类**（无标签）。
- 阈值不是试出来的：是相邻两个不同取值的**中点**。
- 剪枝不是为了提高训练准确率（训练 .989 → .967 反而降），是为了**更小的树和更稳的泛化**。

### 可能被问

- 为什么用 Gini 不用信息增益？Gini 不用算 log，多分类直接算，CART 本来就用 Gini。
- 剪枝为什么用验证集？测试集只在最后看一次，否则评估有偏。
- 过拟合怎么看？不限深度长到底时训练 1.000，但测试只有 .933。
- 和聚类差在哪？聚类没有标签，评价看 SSE / 轮廓 / ARI；分类有标签，看混淆矩阵和准确率。

### 收尾一句

> “分类用 CART，聚类用 K-Means 系列、DBSCAN 和层次聚类；算法都是手写 NumPy，界面把过程录下来回放。谢谢。”
